# ORBITclip 7.8.5 — исправление поиска обновлений

## Исправлено
- Встроенная проверка больше не опирается на `GitHub /releases/latest`. Этот указатель может отставать или быть выставлен вручную на старую версию.
- Теперь приложение запрашивает список опубликованных релизов, пропускает черновики и предварительные версии, сравнивает **числовые номера версий** и выбирает самую новую стабильную.
- Если релиз существует, но обязательный полный архив `ORBITclip_CleanInstall_*.zip` не опубликован или пуст, клиент показывает явную ошибку вместо сообщения «последняя версия».
- Ошибки HTTP 401/404 (например, доступ к приватному репозиторию), 403/429 и отсутствие сети теперь сопровождаются более понятными рекомендациями.
- Для `7.8.2+` сохраняется безопасная накопительная установка полного ZIP за один переход, проверка контрольных сумм и откат.

## Почему 7.8.4 могла не отображаться
Предыдущие клиенты проверяли только `/releases/latest`. Если GitHub возвращал 7.8.3, приложение ошибочно считало, что обновлений нет. Ещё одна возможная причина — отсутствие доступа к приватному релизу без GitHub-токена. Конкретный ответ API для проблемного устройства не был доступен, поэтому эти причины следует различать по тексту сообщения в окне обновлений.

## Как обновиться сейчас
Если установленная 7.8.3 не видит новые версии, перейди к релизу 7.8.5 на GitHub, скачай `ORBITclip_CleanInstall_v7_8_5.zip`, затем выбери **«Настройки → Обновления → Выбрать ZIP…»**. В установленной 7.8.2/7.8.3 полный архив проверяется и устанавливается как накопительное обновление с сохранением пользовательских данных.

В дальнейшем обновления будут обнаруживаться из списка релизов, даже если GitHub пометил более старую версию как `latest`.
