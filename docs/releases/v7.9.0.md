# ORBITclip 7.9.0 — подтверждённая доставка текстовых сообщений

Первая итерация надёжного обмена между Windows и macOS. SQL Studio/SQL Explorer не изменялись.

## Что добавлено
- **Исходящая очередь текстовых сообщений и записей буфера**: если второе устройство временно не отвечает либо включён офлайн-режим, отправка остаётся в локальной очереди вместо потери после ошибки сети. Очередь сохраняется при перезапуске.
- **Доставка подтверждается получателем**: принятие запроса relay-сервером означает лишь «отправлено серверу». Сообщение считается доставленным только после получения зашифрованного подтверждения от второго ORBITclip.
- **Повторные попытки с backoff** до 15 минут между попытками и собственным уникальным ID на каждую отправку. При повторной передаче на получателе не создаётся вторая запись или уведомление — ID сохраняется в локальной истории.
- В мессенджере появилась кнопка **«Очередь · N»** для просмотра ожидающих сообщений и отмены выбранной передачи. Это не удаляет уже полученный собеседником текст.
- В карточке сообщения обозначения: **◷** — ещё нет подтверждения получателя, **✓✓** — получено подтверждение. У старых сообщений без нового протокола отметка **✓** не доказывает получение.
- **Содержимое очереди хранится только в уже E2E-зашифрованном виде** (AES-GCM текущей доверенной пары). Локальный файл не содержит пароль сервера или исходного текста, ограничен 80 сообщениями и 4 МиБ.
- При включении режима «оффлайн» сетевых отправок нет, но подготовленный текст можно положить в очередь. Как только клиент вернётся онлайн и соединение восстановится, отправки возобновятся без дополнительных действий.
- Базовая логика буфера, барабана, категорий, обмена файлами и SQL не затронута.

## Важная совместимость
- Для нового подтверждённого протокола **оба устройства должны быть версии 7.9.0+**.
- Перед отправкой текстового пакета проводится **совместимая со старыми версиями проверка поддержки** (без помещения служебного запроса в историю сообщений). Только клиент 7.9.0+ возвращает нужное подтверждение возможностей; старым устройствам новый текстовый пакет вообще не отправляется. Сообщения остаются у отправителя в очереди до обновления получателя или ручной отмены.
- **Relay по-прежнему не хранит сообщения офлайн**. Очередь хранится на отправляющем компьютере, который должен запуститься и выйти в сеть для повторной отправки. Обмен не работает, если отправитель и получатель ни разу не бывают онлайн одновременно.
- В эту версию входят **только текстовые сообщения и фрагменты**. Крупные файлы до 40 МиБ передаются прежним потоковым механизмом и **ещё не возобновляются после перезапуска**; для этого понадобится отдельная безопасная система контрольных точек.
- Подтверждение означает приём вторым приложением и сохранение сообщения локально, но не гарантирует прочтение человеком.
- Проверки включают имитацию обмена между двумя приложениями, обработку повторных серверных IDs, возобновление очереди после перезапуска и утрату/восстановление подтверждения. Доставка на физических Windows/macOS через конкретный Render-сервер требует отдельного практического теста.

## Установка
Обнови **оба** клиента. Начиная с 7.8.2, можно использовать «Обновления» и накопительный `ORBITclip_CleanInstall_v7_9_0.zip` независимо от пропущенных версий. Для непосредственного перехода 7.8.8 → 7.9.0 также доступен `ORBITclip_Patch_v7_9_0.zip`.
