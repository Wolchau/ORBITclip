# ORBITclip

Настольный менеджер буфера обмена и защищённого обмена фрагментами между устройствами.

**Текущая версия: 7.2.2.** Этот репозиторий — основной источник клиентского кода.

## Запуск

Для Windows: `start_windows.bat`; для macOS: `start_mac.command`.
Нужен Python 3.10+, первый запуск установит зависимости в локальную `.venv`.
Или установите зависимости из `requirements-client.txt` и выполните `python orbitclip.py`.

## Структура

- `orbitclip.py` — Qt-приложение.
- `orbit_*.py`, `kinetic_*.py` — клиентские функции, устройства, безопасность, обработка данных.
- `assets/` — ресурсы интерфейса.
- `patches/v7.2.2/` — установочный патч 7.2.1 → 7.2.2.
- `.github/workflows/` — проверка и формирование GitHub Releases.
- `docs/CONTRIBUTING.md` — работа в разных чатах и параллельные изменения.

## Тестовый токен (временное решение)

**Внимание: этот приватный репозиторий и собираемые из него тестовые ZIP содержат общий токен Render в `client_defaults.json` в открытом виде по запросу владельца.**
Это позволяет быстро проверять взаимодействие нескольких устройств, но **не является безопасной схемой распространения**. Не менять видимость на Public и не публиковать тестовые ZIP.

Перед production: отозвать/заменить токен на Render, удалить его **из всей истории Git (включая старые теги и релизы)** и исключить из сборки клиента. Даже после переписывания Git-истории считать старое значение скомпрометированным.

Сервис релея — отдельный приватный репозиторий `Wolchau/kinetic-relay`.

## Состояние тестирования

Синтаксис и основная модель проверены, но графический запуск на Windows/macOS
необходимо проверять отдельно: GitHub CI не гарантирует работу нативных хуков.

## Релизы

После изменения версии в `orbit_version.py` и слияния в `main` GitHub Actions
формирует ZIP исходников и соответствующий установочный патч (если присутствует).
Релиз помечается `vX.Y.Z`. См. `docs/CONTRIBUTING.md`.

## Первичная загрузка репозитория (один раз)

Если исходники ещё не загружены в новый репозиторий, распакуйте стартовый ZIP и запустите
`publish_to_github_windows.bat` либо `publish_to_github_mac.command`. Требуются Git и
настроенная авторизация в GitHub. Скрипт проверяет состав удалённой ветки и **никогда
не использует принудительный push (`--force`)**. После первой загрузки он не нужен.
